# gen-inhibit/tools/bench/ -- gen-inhibit's bench harness

**Owner:** tester (gen-inhibit). The bench harnesses, judges, runners and rig scripts
for the generator inhibitor, with their tests and mutant runners. They moved here from
SeaDrive's `projects/vtrux/notes/artifacts/gen-inhibit/` on 2026-10-22 (port plan goal
20; the reviewer's rulings of that day), behaviour unchanged: only their paths were
changed, and the public-repo fixes made. Each file's history before the move is in
that SeaDrive folder's records, not in git.

**What stays in SeaDrive** (`$REVERSE_IT_DIR/projects/vtrux/notes/artifacts/gen-inhibit/`):
the run folders and fixtures (`runs/`), the X2 jammer's build binaries and their
`manifest.json` (`x2_jammer/builds/`), the X2 flash dumps (`board-backups/`, never in
git), the one-off checks and corpus investigations, and that folder's index. A row
below that names `runs/...` names a file there.

## Running anything in here

- **`REVERSE_IT_DIR`** must name SeaDrive's reverse-it root (the folder holding `canre/`
  and `projects/`); unset is an error. Everything these tools read or write that is
  not code comes through `gi_paths.py`: captures, vehicle DBCs, the bench lock, run
  records, fixtures and the jammer builds.
- **`canre` is the public repo's, at the commit `pins.json` pins** (the canre-pin step,
  2026-10-26; from SeaDrive before it). Install it once per worktree with
  `py -3.14 -B gen-inhibit/tools/bench/canre_pin.py install`; every tool that parses a
  capture takes it through `gi_paths.use_canre()` or `canre_pin.use()`, which refuse
  any other canre.
- **The diag DBCs come from git, through `gi_diag.py`** (port plan toolkit item 10,
  2026-10-24): the WiCAN's `gen-inhibit/diag/vtrux-wican-diag.dbc`, every schema in its
  history, picked by each frame's schema byte, and the interposer's at a pinned
  `charge-interposer/main` commit. Every tool that decodes a diag page decodes it
  through `gi_diag`, in capture order: a schema no DBC states is refused, and a page
  before the first schema page is undecodable, never decoded with a later schema. The
  RESPOND probe `0x7F0` is outside the schema (it carries no schema version): it decodes
  anywhere in a capture, and `gi_diag` refuses a DBC history in which `WICAN_Probe`'s
  layout is not the same in every DBC (reviewer, 2026-10-25, reading Q8). A
  live run records `gi_diag.run_identity()` (the harness commit and the DBC's commit,
  schema and hash) and is refused if the working tree's DBC is not HEAD's; a re-judge
  holds the record's pages to it. A copy with no git (`~/gi_host`, B15host's
  `~/gi_bench_<commit>`) gets `gi_diag`'s `diag_schemas/` export beside it.
- **Run records never land in the repo.** A tool's default output folder is SeaDrive's
  `runs/`; `GI_RUNS_DIR` (and the runners' `GI_OUT`) still point a run elsewhere.
- The shell runners (`baseline_*.sh`, `b6_*.sh`, `x2_release_identify.sh`) change to
  `$REVERSE_IT_DIR` themselves and take their data relative to it, as they did when they
  ran from there. The chain suite (`../suite_gen_inhibit.py`) runs them from here.
- **Retired, and refused if set:** `GI_FW_TOOLS` (the tools find `gen-inhibit/tools/` as
  their parent folder), `GEN_INHIBIT_REPO`, `VTRUX_DATA`, `REVERSE_IT_ROOT`.
- **The project layout** (port step 0d, 2026-10-26). Since then gen-inhibit's tree is
  under `gen-inhibit/`: the WiCAN tree, the IDF build root, in `firmware/`, the tooling
  flat in `tools/` (this folder is `tools/bench/`), the tests in `test/`.
  `gi_paths.project_root()` is `gen-inhibit/` (a copy with no git, such as `~/gi_host`,
  has the same layout), `gi_paths.firmware_root()` its `firmware/` (`main/`, the build
  folders, `vtrux_checks.json`), and `gi_paths.repo_root()` the repo root above it: the
  worktree's `scratch/`, and what git's repo-relative paths, such as `gen-inhibit/diag/`,
  are relative to. A project path at another commit goes through `gi_paths.path_at()`,
  which reads each commit at its own layout: under `gen-inhibit/` where that commit has
  it there, else where it was before the move (`gi_paths.old_path()`: `main/` at the
  root, the tooling in `tools/gen_inhibit/`). `golden_schema_bump_check.py` uses it;
  `baseline_host_run.sh` does the same in shell.
- **Old run records keep the paths they were written with** (the harness at the repo
  root, `tools/gen_inhibit/...`, in a chain record's settings and argv). They are
  history and stay as written. Nothing reads a harness path back from a record: a
  re-judge runs this tree's tools on the record's data, found through
  `REVERSE_IT_DIR`, and a git path a record names (`gi_diag`'s `dbc_path`) is read at
  the record's own commit, whose tree the move did not change.
- **Settings, never committed:** `GI_CHAIN_SETTINGS` (the chain settings file:
  `test_chain_settings_chip.py`, and `ota_rollback_rehearsal.py`'s WiCAN MAC and device
  id, keys `wican.base_mac` and `wican.device_id`); `IDF_PATH` and `GI_IDF_PYTHON` (the
  32-bit Python 3.11 folder ESP-IDF's `export.ps1` needs) for the `.ps1` build scripts.
  The values for each machine are in reverse-it's `tools-reference.md`.
- **Pins** (toolkit item 9): `pins.json` holds the sha256 of the SeaDrive inputs the
  harness depends on (captures, cut replays, DBCs, the jammer binaries, and the run
  records the tests read), and a digest for each fixture folder. A tool that resolves a
  pinned input refuses it if it has changed. Two more sections pin what comes from git:
  `git` (the interposer's diag DBC: its `charge-interposer/main` commit and sha256) and
  `core` (`shared/bench`'s `vtrux_bench/decode.py`: the suite's core pin `b9896a0` and
  the file's git blob id), both checked by `gi_diag.py`.
- Python is `py -3.14 -B` on NICKY-XPS (`python-executables-reference.md` in reverse-it).
  Tests and mutant runners work in the worktree's gitignored `scratch/`, never the system
  temp folder: `gi_paths.scratch(name)` gives each run its own
  `scratch/gen-inhibit-tests/<name>/<time>_<pid>`, so two runs at once, from two sessions or
  worktrees, never share a folder (2026-10-24; before, most used one fixed folder in the
  temp folder, and two runs at once overwrote each other). A copy of a test in a mutant's
  folder finds the same worktree, by walking up to its `.git`.
