# Dependencies for the Vtrux charge-interposer bench.
#   <python> -m pip install -r charge-interposer/requirements.txt

# CAN transport. The default 'virtual' transport uses python-can's built-in
# udp_multicast backend -- no hardware, no admin rights.
python-can>=4.0

# Required by python-can's udp_multicast backend, which is what the default
# 'virtual' transport uses. python-can does NOT pull it in: without it every
# simulator dies at startup with
#   CanInterfaceNotImplementedError: msgpack not installed
# and the scenario fails every expectation in about two seconds.
# Found on NICKY-XPS, 2026-09-19.
msgpack

# DBC encode/decode for the BMS and charger frames in protocol.py, and the
# reference implementation test_signals.py checks machine.py against.
# machine.py itself imports nothing.
cantools>=39

# The X2's USB serial port: run_scenario's SerialTap and board reset,
# bench_identify and the bench drivers. bench_suite_test's argv probe
# imports it too, so its suite fails without it, hardware or not. Missing
# from this file until madhouse-debian, where python3.13 lacked it
# (installed there with pip --user, pyserial 3.5, user 2026-11-11).
pyserial

# Only needed for the real-dongle transports (ixxat / kvaser / pcan /
# socketcan / gs_usb). All but gs_usb auto-detect via
# canbench.live.receiver; canbench is not installed from here but loaded
# from the pinned can-tools commit, written out of the clone at
# CAN_TOOLS_DIR by `can_tools_pin.py install` (paths.import_canbench).
# libusb-package
# pyusb
