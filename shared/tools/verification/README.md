# shared/tools/verification

**Owner:** tester (gen-inhibit; C6f, reviewer ruling 2026-10-24).

The tester's verification of the build tooling against `../SPEC.md`. The
expected values come from SPEC and from ESP-IDF's published app image format,
never from `vtrux_build`'s source: `independent.py` is the tester's own reading,
and each check compares the library's answer with it, or tests a property SPEC
states. The build checks (R17, R18, R20, R21, R29, R30) are not here; they are in
`../vtrux_checks/`, and their real-build cases are here. R19 is a test of the
tooling, not a check, and is here (`repro_cases.py`).

Each script has a `--self-test` that runs the same checks against fake
libraries: each fake breaks one rule and must be caught, and one fake breaks
none and must pass. A check that no fake can fail is not a check.

| `independent.py` | The tester's reading of R1 and R2: the image layout, the ranges R2 blanks, the code hash and the image hash. It also builds valid synthetic images and changes one field or byte while keeping the image valid. `scratch(name)` gives a run its own folder in the worktree's `scratch/shared-tools-verification/`, removed when the process exits, pass or fail. `remove_tree(path)` is the one remover every script here uses (`release_cases.rmtree` calls it and raises when anything is left), per AGENTS.md "Removing scratch": it clears the read-only flag and retries, uses `\\?\` paths on Windows, and prints what it could not remove and why, returning False. `--self-test` runs the remover against 6 fakes: errors ignored, no read-only retry, no `\\?\` prefix, success trusted without looking, nothing printed, and no removal at exit. Its cases: a clone-like tree (a read-only file in `.git/objects`, a path past 260 characters and, on Windows, a folder whose name ends in a dot, which only a `\\?\` path reaches), a tree it cannot remove (a file held open on Windows, a read-only folder elsewhere), and a child process's `scratch()` folder, gone after it exits, or printed when a file in it is still held at exit. The two Windows-only fakes are not run elsewhere, and the cannot-remove cases are skipped when running as root. |
| `verify_image.py` | R1, R2 and R15 (the library side). On synthetic images: the code hash and its blanked ranges, which fields keep it and which change it, refusal of a truncated, padded or badly sealed image, and that reading never patches the file. With `--same`, `--different` and `--expect-code`, on real images: the same checks, plus one shared code hash across builds of the same files. Where an `.elf` sits beside a `.bin`, it also checks R1 against the ELF's sha256. 8 fakes. |

## Running

From this folder, with the Python command in `local-paths.md` and `-B` (a
`__pycache__` in `shared/tools/` changes its digest):

```
py -3.14 -B independent.py --self-test
py -3.14 -B verify_image.py --self-test
py -3.14 -B verify_image.py [--same A.bin B.bin ...] [--different C.bin] [--expect-code PREFIX]
py -3.14 -B verify_digest.py --self-test
py -3.14 -B verify_digest.py [--commit <commit> [--component shared/tools]]
py -3.14 -B release_cases.py --self-test
py -3.14 -B scope_cases.py --self-test
py -3.14 -B options_cases.py --self-test
py -3.14 -B repro_cases.py --self-test
py -3.14 -B switches_cases.py --self-test
py -3.14 -B board_cases.py --self-test
py -3.14 -B pins_cases.py --self-test
py -3.14 -B env_cases.py --self-test
```

`scope_cases.py`, `options_cases.py`, `pins_cases.py`, `repro_cases.py` and `env_cases.py` run like `release_cases.py`, with the
same `--root` (the fixture must already be there) and `--out`; `env_cases.py` also takes
`--other-idf <file>`, written by `python -B env_cases.py --dump-env <file>` in a shell exported
for the other ESP-IDF install (the file names local paths: keep it in `scratch/`); `switches_cases.py` takes `--base`
and makes its fixture in a `--root` of its own; `options_cases.py` also takes
`--profile`, `board_cases.py` `--board`, and `repro_cases.py` takes `--keep` to keep each case's two builds.

`release_cases.py` runs from an exported ESP-IDF shell, with its Python:
`python -B release_cases.py --root <short folder in scratch/> --out <run folder>
--base <gen-inhibit commit> [--cases a,b] [--jobs N] [--fixture <repo>]`.
`--base` is resolved in this checkout's repository, where `gen-inhibit/main` (the default) is a
branch, and must be a commit the fixture's clone has (before 2026-11-04 it was resolved in the
clone, which has that branch only as `origin/gen-inhibit/main`, and the default failed).
Set `REAL_REVERSE_IT_DIR` to the real reverse-it folder so it can read the "No
builds" line. Keep `--root` short: the IDF build paths under it are long. Commit the
tooling first: the fixture tags this checkout's HEAD, and a `--root` whose tag marks another
commit is refused, so a new commit needs a new `--root`.

Exit 0 is all ok, 1 is a FAIL. The run records go to the gen-inhibit harness
folder in reverse-it (`projects/vtrux/notes/artifacts/gen-inhibit/runs/`), and
the results to `../VERIFICATION.md`.
