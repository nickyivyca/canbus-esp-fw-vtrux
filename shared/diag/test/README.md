# shared/diag/test/: the tester's checks of shared/diag

The testers' (shared/diag `README.md`: "the parity test of the C and Python packers
(D4), each project's DBC check (D3) and any other test that verifies the component").
Written by the gen-inhibit tester on 2026-11-23, for gen-inhibit's stage (b) batch 2,
against `SPEC.md` D2-D4. Each project's own check that its committed tables are its
DBC's, regenerated byte for byte, is the project's (gen-inhibit's is
`test/build_checks/build_output.py`'s `check_diag_table()`).

`verify_diag.py` generates tables from a DBC with the generator under test and judges
them, and both packers, against that DBC as cantools reads it, never against the
packers' own code:

- **D3, the table is the DBC's:** the C table, the Python `MESSAGES` and the header's
  per-signal `__BITS`, `__SIGNED` and index constants and per-message `__ID` give every
  message's id, extended flag and DLC, and every signal's start bit as written, length,
  byte order, signedness and multiplexing, as cantools does.
- **D3, a misfit is reported, not truncated:** value vectors with fitting, edge, misfit
  and far values, through both packers. The count and the mask are the packed signals
  whose value is outside the signal's range, and the bytes are cantools' encode of the
  same values with each misfit left 0. A selector that does not fit gives -1 and a zeroed
  frame. The C packer is handed a frame of A5 bytes, so one that does not zero it shows.
- **D4, C and Python agree:** the same vectors give the same result and bytes (and mask,
  where the result is not -1), and both range functions give the ranges the widths do.
- **D2, the build id:** for hashes made here and four edge hashes,
  `diag_build_id_from()` and `diag_build_id()` (over the driver's descriptor) give hash
  bytes 0-3 with byte 0 most significant. Packed into a 32-bit unsigned Intel signal,
  the wire bytes are hash[3..0], and the DBC's value printed `%08x` reads as the hash's
  first four bytes.

The DBCs are `fixtures/verify.dbc` and each project's published diag DBC as origin's main
branch holds it. A DBC missing from the repo is NOT RUN, never a pass. A generator
refusing a DBC, or the C side crashing under ASan or UBSan, is a failed check.

| File | What |
|---|---|
| `verify_diag.py` | The checks above. `--diag DIR` tests another shared/diag folder; `--n` vectors per message (400); `--seed`; `--no-git` the fixture only. Exit 0 pass, 1 a check failed, 2 refused (no cantools). |
| `driver.c` | The C side's driver: the table dump, the header's constants (a file `verify_diag.py` writes per table), `diag_pack_message()`, the range functions and the build id, one command per stdin line. Built per table with ASan and UBSan. |
| `host/esp_app_desc.h` | A host stand-in for ESP-IDF's header, the one field D2 reads; the driver defines `esp_app_get_description()`. |
| `fixtures/verify.dbc` | Intel and Motorola, signed and unsigned, 1 to 64 bits (7 and 12 bits across bytes, 63 and 64), a 3-byte frame, one multiplexer with a Motorola page, an extended id, and the build id's page. `DiagSchemaHash` is its `layout_hash` (shared/bench `decode.py`). |
| `mutate.py` | The can-fails: 27 one-line defects planted in a copy of shared/diag, 11 in the C packer, 5 in the Python twin, 9 in the generator, 2 in the build id. `verify_diag.py` must fail each, and an unedited copy must pass. |

```
PYTHONDONTWRITEBYTECODE=1 python3.13 -B shared/diag/test/verify_diag.py
PYTHONDONTWRITEBYTECODE=1 python3.13 -B shared/diag/test/mutate.py
```

Run from the worktree root, in `build.slice` on madhouse. They need cantools and `cc`
with ASan and UBSan. Work goes to `scratch/diag-verify/<pid>/` and
`scratch/diag-mutants/<pid>/` at the worktree root, removed afterwards.
